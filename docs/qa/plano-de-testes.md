# PLANO DE TESTES — PORTFÓLIO DANIEL POUBEL

## 1. Identificação do projeto

- **Projeto:** Portfólio Profissional — Daniel Poubel
- **Tipo:** Aplicação Web estática
- **Tecnologias:** HTML5, CSS3 e JavaScript
- **Hospedagem:** GitHub Pages
- **Responsável pelo desenvolvimento e QA:** Daniel Poubel

## 2. Objetivo

Documentar o planejamento e a execução dos testes de qualidade realizados durante o desenvolvimento do portfólio, verificando funcionamento, apresentação visual, responsividade, acessibilidade, desempenho e SEO.

## 3. Escopo dos testes

- Carregamento e navegação entre páginas.
- Funcionamento dos elementos interativos.
- Exibição de imagens e logotipos.
- Alternância entre temas claro e escuro.
- Funcionamento do carrossel.
- Responsividade da interface.
- Estrutura HTML e estilos CSS.
- Verificação de erros JavaScript.
- Desempenho, acessibilidade e SEO.

## 4. Ferramentas utilizadas

| Ferramenta | Finalidade |
|---|---|
| Google Chrome DevTools — Console | Investigação de erros JavaScript |
| Google Chrome DevTools — Elements | Inspeção da estrutura HTML e estilos CSS |
| Google Chrome DevTools — Device Toolbar | Verificação da responsividade |
| Lighthouse | Avaliação de performance, acessibilidade, boas práticas e SEO |
| Navegador Google Chrome | Execução dos testes funcionais e visuais |
| Git e GitHub | Versionamento e publicação |

## 5. Estratégia de testes

Os testes foram conduzidos durante o desenvolvimento, com identificação de problemas, análise das possíveis causas, correção do código e retestes no navegador.

Foram considerados:

- Testes funcionais.
- Testes visuais.
- Testes de responsividade.
- Verificações de acessibilidade.
- Avaliação de desempenho.
- Verificações de SEO.
- Revisão de boas práticas de segurança.

## 6. Critérios de aprovação

Um teste será aprovado quando o comportamento observado corresponder ao resultado esperado.

Quando um defeito for identificado, deverá ser registrado, corrigido e submetido a reteste.

## 7. Critérios de encerramento

- Testes executados e resultados documentados.
- Correções identificadas e verificadas.
- Versão publicada conferida no GitHub Pages.
- Relatório final de QA atualizado.
- Aprovação e encerramento da revisão.
